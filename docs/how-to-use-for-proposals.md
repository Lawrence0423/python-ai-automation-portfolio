# How to Use This Portfolio for Proposals

Use this portfolio as proof that you can deliver scoped Python and AI automation work.

## Proposal workflow

1. Read the client post and identify the closest demo.
2. Mention the matching demo in the first half of your proposal.
3. Ask 2-4 practical clarification questions.
4. Propose a small first milestone.
5. Avoid promising the full platform before seeing the code, API docs, and test data.

## Which demo to link

| Client post says | Link this demo | Proposal angle |
| --- | --- | --- |
| Chatbot, FAQ, support agent, OpenAI | `demo-1-ai-chatbot` | Knowledge base first, safe fallback, API integration |
| CRM, lead routing, Make, Zapier, workflow | `demo-2-automation-workflow` | Approved data intake, scoring, review queue, API payloads |
| Scraping, API extraction, CSV, Excel report | `demo-3-data-extraction` | Approved sources, normalization, validation, report output |

## First message structure

Use this structure:

```text
Hi, I can help with this.

I would build the first milestone as [one concrete workflow].
I have a small demo of a similar pattern here: [link].

For your project, I would adapt it to [their API/data/workflow].

Before estimating final timing, I would like to confirm:
- [question 1]
- [question 2]
- [question 3]
```

## Scope control language

Use this when a post is broad:

```text
To keep the first milestone reliable, I would start with one complete workflow rather than the full platform. After the MVP is approved, we can add more integrations and automation steps.
```

## Red flags

Be careful when a client asks for:

- "Bypass" anything
- Mass messaging
- Fake accounts or fake reviews
- Scraping behind a paywall
- "Production-ready" work on a very small fixed budget
- Vague AI accuracy targets without a test set
